# Step 13B — Finance transaction foundation

Apply the patch over Step 13A. No schema migration or dependency change. Finance uses the existing audited idempotency transaction helper with a finance-specific operation namespace. Project-level lock serializes financial changes; existing policy's maker/checker is retained. PM may draft only for assigned projects; finance managers/admins manage budgets and voids. Category creation is organization-scoped. New budgets are created on Finance page for existing projects, not in project creation. Existing project creation authorization is unchanged.

GET /api/v1/finance?projectId=...&page=1 returns 20 expenses, budget totals, categories (first 100) and latest 20 revisions. POST accepts strict discriminated actions category, budget, draft, post, void. Idempotency-Key and same Origin required. Monetary input is a decimal string, BDT, max 16 integral digits and two decimal places. Budget changes use expected previous amount to prevent stale overwrites. A draft is not actual cost. A void preserves original transaction and audit history; a replacement is a separate draft. No destructive deletion endpoint.

Known limitations: no editing drafts, explicit linked void/replacement, expense attachment UI, persistent overrun notifications, monthly trends, complete category/project pagination or revision-history pagination yet. Current project list excludes archived projects. Overrun is a live on-screen warning, not a persisted notification. Construction replay vulnerability from Step 13A remains outside this patch. Finance integration fixtures intentionally remain in isolated buildtrack_auth_test (append-only history). Full local runtime verification required.
