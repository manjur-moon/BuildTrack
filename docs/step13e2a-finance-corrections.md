# Step 13E.2A — financial corrections and initial budget

Apply the new migration to each local database before running the changed services. Use `prisma migrate deploy --config prisma7.config.ts`, then `npm run db:generate`. Never reset a populated database. The migration adds a nullable self-reference, composite foreign key, unique successor index and a correction guard trigger. Existing records remain unchanged. Existing posting and deletion triggers remain in place.

- Project creation accepts optional `initialBudget` (BDT string, 0 to 9999999999999999.99); the approved and initial amount and budget audit are committed with the project and creation idempotency record. Leaving it blank preserves unbudgeted projects.
- Only the original recorder with live expense creation permission can edit their own DRAFT. This avoids allowing an approver to edit someone else's draft then approve their own changes. Posting still requires a different authorized person. Edit, post, void and replace require the exact `expectedUpdatedAt` from the ledger; refresh on 409.
- `replace` requires a current POSTED original and financial management authorization. It voids the original and creates a linked DRAFT together, with two audit records. A different authorized member must post the replacement. Actual spend temporarily decreases until replacement posting. A plain void is still available and does not create a replacement. Previously voided expenses cannot use this action retroactively.
- A replacement has a single predecessor in the same tenant and project, and cannot have its link reassigned or be deleted. A later correction can extend the chain. Existing private attachments are not copied, modified or introduced by this patch.
- The old `post` and `void` HTTP payloads without a version now fail validation. The UI and repository finance integration callers are updated. Existing idempotency records for old payloads are not replay-compatible with the new versioned payload. Do not use new keys to retry uncertain old mutations; refresh the ledger first.

Local tests: `npm run test -- tests/finance/corrections-input.test.ts tests/finance/money.test.ts tests/construction/input.test.ts`, `node --test tests/finance/corrections.static.test.mjs`, and `RUN_FINANCE_INTEGRATION=1` only on the isolated PostgreSQL test database. The integration suite now contains two cases with multiple assertions. Full Prisma validation, DB execution and typecheck are required locally. Expense uploads and private storage verification, remaining contractor coverage and E2E are separate steps.
