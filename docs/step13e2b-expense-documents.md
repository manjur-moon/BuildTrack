# Step 13E.2B — Private expense documents

Apply only on top of 13E.2A. No Prisma migration, new dependencies or new environment variables. Do not deploy before local verification. Use a development branch, and retain the currently deployed commit. Do not use production/demo Neon for tests.

Existing private S3 bucket must allow application/pdf as well as image/jpeg, image/png and image/webp. Keep the existing bucket private. Max upload is 8 MiB; bucket's 10 MB limit may remain unchanged. PDF uploads are format sanity checked only, not malware scanned. Only trusted demonstration files should be used. Images are decoded and normalized to WebP, not byte-identical originals. Downloads use a 60-second signed URL, attachment disposition, and no public object URLs. Supabase behavior must be tested live. No original invoice-image preservation or object-level immutable retention is provided.

Expense documents use FileAttachment.expenseId as the sole parent (no projectId). Scope derives from expense and current organization. Recorder-only draft changes use the existing project lock shared with finance mutations, live RBAC, and monotonic expense version. A pending attachment blocks posting. Posted/voided documents stay with their original expense; replacements do not inherit them. Audit events log initiation, completion and removal. Existing site media API explicitly excludes expense records. Pending drafts can be removed; upload completion retries safely return existing READY id when draft remains editable. A version mismatch requires refreshing ledger. Initiation/removal use actor-bound idempotency; signing occurs after transaction and signed URLs are never stored in replay records.

Storage and database cannot share a transaction. A unique final key per completion prevents overwriting evidence if competing requests upload concurrently. In a failed/uncertain commit, the unreferenced final object is retained for eventual reconciliation; abandoned quarantine objects and removed objects may likewise need cleanup. No scheduled cleanup, malware scanning, PDF parsing, per-tenant storage quota, or database-level trigger preventing direct attachment table writes is added. Presigned URLs remain usable until expiry even after revocation. Archived projects follow existing finance read restrictions. Do not use for sensitive real customer documents until these gaps are addressed.

Integration tests mock storage; separately test PDF and image upload/download, removing pending/ready draft documents, stale approval rejection, independent posting and voiding, no public bucket access. Confirm deployed preview credentials and environment targets before any push. Never expose S3 credentials in frontend or Git.
